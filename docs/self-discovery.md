# Self-discovery: the pool without Git

Status: implemented on `feat/self-discovery`.

## Goal

Pinball builds its own model pool from what the configured upstream serves,
infers `light`/`standard`/`heavy` from model capabilities, and needs nothing
after install except its config. No Git, Gitea or bot PRs anywhere in a
deployed stack.

## Pieces

1. **Shipped catalogue** (`src/pinball/catalog.json`): one entry per model id,
   provider-agnostic. Built by `scripts/build_catalog.py` from
   [models.dev](https://models.dev/api.json) (MIT) plus the Terminal-Bench
   leaderboard. Fields: `family`, `context`, `input`, `output`,
   `cost_in`/`cost_out` (USD per 1M), `vision`, `tools`, `reasoning`,
   `efforts` (allowed `reasoning_effort` words, empty when the model takes a
   token budget or nothing), `api` (`chat`, `responses`, `messages`),
   `tbench` (best accuracy, 0-100, absent when not on the board).
   Regenerated by a maintainer or a scheduled CI job and released with the
   image; a deployment never fetches it.

2. **Live discovery** (`PINBALL_DISCOVERY_URL`, the upstream `/v1/models`,
   with optional `PINBALL_DISCOVERY_TOKEN`). At start and every
   `PINBALL_DISCOVERY_INTERVAL_SECONDS` (default 6 h) pinball lists the
   models the user can reach. Live fields win over the catalogue: Copilot's
   `model_picker_category`, `supported_endpoints`,
   `capabilities.limits.max_prompt_tokens`, `capabilities.supports`
   (`vision`, `reasoning_effort`); Anthropic's `max_input_tokens` and
   `capabilities`; Gemini's `inputTokenLimit`; anything else falls back to
   the catalogue, then to conservative defaults. Non-chat, embedding and
   dated-snapshot ids are skipped.

3. **Tier inference** (`src/pinball/discovery.py`), first rule that applies:
   - vendor category: Copilot `lightweight`/`versatile`/`powerful` map to
     light/standard/heavy;
   - Terminal-Bench accuracy: `>= heavy_tbench` (55) heavy, `>= standard_tbench`
     (35) standard, else light;
   - output price per 1M: `<= 2` light, `>= 20` heavy, else standard;
   - unknown: standard (the safe middle; the optimizer may move it later).
   Within a tier, models are ordered by tbench (desc), then output price (asc),
   then id, so the default pick is the strongest known, cheapest on ties.
   Every tier must end up non-empty; an empty tier borrows the nearest
   neighbour's best model.

4. **Request constraints**: `_pick` skips a model that cannot serve the
   request's API shape (body: `input`/`instructions` = responses,
   top-level `system` or `anthropic_version` = messages, else chat) or that
   rejects the request's `reasoning_effort` word. Unknown shapes and models
   without data are not restricted.

5. **State**: the last good discovered pool is written to
   `PINBALL_DISCOVERY_CACHE` (the PVC on k8s) so a restart with the upstream
   down still serves it. Order of precedence at start: live, cache, the
   static `models`/`tiers` in `pinball.yaml`.

6. **Static config still works.** Without `PINBALL_DISCOVERY_URL` nothing
   changes. With it, `pinball.yaml`'s `models`/`tiers` are the fallback, and
   `pin` (optional) forces named models to the front of a tier.

7. **Optimizer**: the Gitea/bot new-model path (`gitea.py`, `bot.py`,
   `carrier_edit.py`, `newmodels.py`, `discovery_cli.py`) is removed.
   Reordering within tiers stays in the overlay file, unchanged. Since the
   pool is discovered, a newly listed model is routable at once, and the
   overlay ranks it after judged replays.

## Gateway side (Convergence)

agentgateway routes one wildcard virtual model with
`transformation.model: 'default(extauthz.model, llmRequest.model)'`, so any
id pinball returns is accepted without rendering the pool into the gateway.
